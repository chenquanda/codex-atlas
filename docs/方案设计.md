# 方案设计

本文记录 Codex Atlas Rust/Tauri 重写版当前架构。目标是让后续实现者理解边界：外部 Codex 数据只读，项目内 `data` 保存用户数据和缓存，Rust 负责可信文件系统与命令边界，React 负责主界面和详情窗口交互。

## 架构

项目采用 Rust + Tauri v2 + React + TypeScript。前端位于 `src`，通过 `src/api/atlasApi.ts` 调用 Tauri commands；后端位于 `src-tauri/src`，按领域拆成 `domain`、`scanner`、`stats`、`store`、`skilldoc`、`translate`、`commands`、`app_state` 等模块。

React 主界面负责搜索、筛选、排序、选择、元数据编辑、复制模板和打开详情。Rust 后端负责扫描真实文件、解析统计、读写项目数据、限制路径边界、执行翻译命令和创建 Tauri 详情窗口。Tauri IPC 只暴露结构化 command，不把文件路径直接塞进 URL；详情窗口 URL 只携带编码后的 skill id，文件列表和内容仍通过后端 command 获取。

## 数据模型和三层合并

核心类型是 `Ability`，包含 `id`、`name`、`kind`、`path`、`summary`、`raw_tags`、`ai`、`user`、`stats`。数据分三层：raw、AI、user。raw 来自扫描，只描述外部 Codex 能力事实；AI 层用于中文摘要、AI 标签、调用模板和场景；user 层用于别名、手动标签、备注、收藏、隐藏、自定义模板。

合并时用户优先。用户标签存在或 `tags_overridden` 为真时，不回退到 AI 标签或 raw 标签；用户自定义模板优先于 AI 模板；别名优先于扫描名称；中文摘要优先于英文 summary 展示。扫描刷新只替换 raw abilities，不能覆盖 user、AI、stats 映射。

## Scanner

`scanner` 支持扫描普通 skills、插件 skills，以及由 manifest 输入的 plugins、tools、apps catalog。默认应用状态会配置 `.codex\skills`、`.agents\skills` 和 `.codex\plugins`，并只在文件真实存在时接入常见 catalog manifest：`.codex\plugins\plugins.json`、`.codex\plugins.json`、`.codex\tools\tools.json`、`.codex\tools.json`、`.codex\apps\apps.json`、`.codex\apps.json`。缺失 manifest 会跳过，不产生 warning；已接入 manifest 会被解析为可展示 Ability。

插件 Skill id 规则是 `pluginName:skillName`，普通 Skill 是 `skill:skillName`。版本化插件缓存会从路径中推导插件名，避免把版本号当插件名。id 片段会转小写并规范化，只保留 ASCII 字母、数字、下划线、点和短横线，其他字符折叠为短横线。

扫描器使用显式栈、最大深度和 canonical 路径校验。根目录和子目录会拒绝 symlink，并通过 canonical 校验阻止目录联接、重解析点或其他真实路径逃逸；子路径 canonicalize 后必须仍在扫描根目录内。单个坏 `SKILL.md`、坏 manifest、过大文件、读取失败或 JSON 解析失败只产生 warning，不中断全局扫描，这样一个坏文件不会让整个 UI 变空。

## Stats

统计模块输出 `Stats { usage_count, last_used_at }`，当前核心字段是 `usage_count`。`Some(N)` 表示有可信统计，前端显示 `N 使用`；`None` 表示未知，前端显示 `未统计`。未知不能写成 `Some(0)`。

计数来源有两类：用户消息里显式 `$skill` 或 `$plugin:skill`，以及助手消息或结构化字段里带读取信号的 `SKILL.md` 路径。用户显式点名会逐次累加；助手读取会根据 Skill 路径 marker 做最佳匹配，避免同名 Skill 的短后缀误计。system、developer、tool、function 等角色里的技能清单、约束和工具回显被视为噪音，不参与统计。

统计 discovery 如果会话目录不存在、目录被截断、文件读取失败、JSONL 行解析失败或根目录为空，会把结果标记为不完整。不完整统计可以用于当次展示 warning，但不能保存为权威缓存，避免把“未读到数据”覆盖成 0。

## Store 和 cache

项目持久化集中在 `data`。`data/store.json` 保存 raw abilities、user_data、ai_data、stats 四块权威数据；`data/stats-cache.json` 保存完整统计刷新后的可重建缓存；`data/translation-cache.json` 保存单文件译文缓存。

所有 store 和 stats cache 路径都通过项目 `data` 目录解析，拒绝逃逸路径。保存采用临时文件写入、flush/sync、再替换目标的方式；Windows 上已有目标文件时会使用备份回滚策略，避免半截 JSON 留在权威文件中。翻译缓存同样先写 `.tmp` 临时文件，再原子替换 `data/translation-cache.json`，并在失败时清理临时文件。

用户数据保护原则是：扫描刷新不能清空用户整理，统计不完整不能覆盖未知或已有统计，翻译失败不能改写 store，坏 JSON store 会降级为空并给出 warning，而不是让应用崩溃。

## Skilldoc

`skilldoc` 负责 Skill 详情窗口的文件列表和只读文件内容。入口能力必须是 `AbilityKind::Skill`，且 path 必须指向真实可读文件。后端先解析 canonical Skill 根目录，再对每次相对路径读取做标准化和 canonical 校验：拒绝绝对路径、`..`、空路径、symlink 逃逸和目录联接逃逸。

文件列表只展示可读文本类型，支持 Markdown、文本、JSON/YAML/TOML、代码、样式、Shell、PowerShell、SQL、配置等扩展。`node_modules`、`target`、`.git`、`.cache`、`dist`、`build` 等目录会跳过；文件数量、目录深度和单文件大小都有上限。二进制样本、非 UTF-8 文本和过大文件不会进入阅读器。

## Translate

翻译模块只处理当前打开的单个 Skill 文件。`get_translation_state` 读取当前文件，计算 content hash，并检查 `data/translation-cache.json`；中文内容不显示翻译动作，非中文且无缓存时才显示按钮。缓存命中时默认返回译文。

真正翻译通过 `codex exec --ephemeral` 执行，工作目录是项目根目录，`TEMP/TMP` 指向项目 `.tmp`。模块会在 `.tmp` 写入 prompt、input、output、stdout、stderr 文件，设置 120 秒超时，通过 stdin 传 prompt，避免长 Skill 内容进入命令行参数。命令失败、超时、空输出会转成结构化错误给前端展示。

缓存 key 是 `skill_id`、`relative_path`、`content_hash` 的长度前缀组合，避免简单字符串拼接碰撞。保存缓存时使用全局锁和原子替换，翻译请求文件、stdout/stderr/output 临时文件通过清理器在流程结束后删除。

## Smoke 和 build

验证分四层。`scripts/验证项目骨架.ps1` 检查核心项目骨架、smoke 脚本、Playwright 配置、`dist\说明.md`、Tauri 图标、项目内缓存目录、CSS 不使用 `vw` 字体、Tauri dev/build 必须经 `scripts/设置开发环境.ps1`，并确认生成 schema 目录被 `.gitignore` 忽略。

`smoke:scan` 只读探测真实 Codex roots，使用最大深度和目录数量上限，找到真实 Skill-like 数据后运行 Rust `real_scan_smoke`；无数据时跳过。`smoke:skill-detail` 运行 Skill 文件阅读相关 Rust 测试和前端测试。`smoke:translation-cache` 使用 fake runner 验证翻译缓存，不调用真实 Codex。`smoke:gui` 启动脚本自己的 Vite server，安装/使用项目 `.cache` 里的 Chromium，并运行 Playwright 测试；它 mock Tauri IPC，不验证真实后端。

打包路径由 `scripts/设置开发环境.ps1` 控制。`npm run build` 生成 `dist`，`npm run tauri:build` 通过 Tauri v2 读取 `frontendDist` 并把 Cargo target 放到 `.cache\cargo-target`。`src-tauri\icons\icon.ico` 是当前 Tauri build 所需的轻量图标，属于骨架的一部分。
