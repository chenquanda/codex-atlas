## 重要审查发现与修复摘要

Important：翻译结构化错误不够清晰。早期翻译 command 失败时前端只能拿到普通字符串，无法区分超时、命令失败、空输出、缓存 JSON 错误或中文文件误翻译。修复后，Tauri command 返回 `TranslationCommandError`，包含 `kind`、`message`、`status_code`、`stdout`、`stderr`、`timeout_millis` 等字段，前端仍展示中文消息，但后续测试和排障可以判断错误类型。

Important：翻译缓存原子替换和临时文件清理不足。早期缓存保存如果中途失败，可能留下半截 JSON 或残留 prompt/input/output 文件。修复后，translation cache 先写项目 `.tmp` 临时文件并 sync，再用平台替换语义覆盖 `data/translation-cache.json`；请求输入、提示词、stdout、stderr 和 output 都有清理流程，失败时也尽量移除临时文件。

Important：`smoke-scan` 真实数据预探测曾存在无界递归风险。修复后，PowerShell smoke 使用显式队列、最大深度、最大目录数量、reparse point 跳过和真实文件判断，镜像 Rust scanner 的边界；没有可扫描真实数据时明确跳过，不把空环境当失败。

Important：统计不完整时不能保存为可信 0。修复后，stats discovery 和 JSONL 解析只要出现缺目录、读文件失败、坏行或截断，就把报告标记为 incomplete；不完整结果不会写入 stats cache 或权威 store，UI 保持 `未统计` 或已有统计。

Important：Skill 详情文件读取必须防目录逃逸。修复后，入口 path、相对路径、目标文件都会经过 canonical 校验；绝对路径、`..`、symlink、目录联接、非文本、过大文件和二进制内容被拒绝或跳过。

## 已知剩余风险和限制

- 翻译仍是用户手动触发的单文件操作，真实调用依赖本机 `codex` CLI 可用性和网络/模型状态；当前 smoke 使用 fake runner，不覆盖真实模型质量。
- GUI smoke mock Tauri IPC，能覆盖前端交互和布局状态，但不能证明真实 Tauri command 与窗口创建在所有机器上都正常。
- 真实扫描 smoke 会在没有本机 Codex Skill-like 数据时跳过，因此空环境无法证明 scanner 对真实数据的数量合理性。
- 使用统计依赖 Codex sessions JSONL 的结构稳定性；已覆盖常见角色和结构化字段，但未来 Codex 日志格式变化时需要补测试。
- 当前文档覆盖已实现骨架和任务 9 后事实，后续如果加入 AI 批量整理、设置页或更多平台支持，需要同步更新 README、使用说明和方案设计。
