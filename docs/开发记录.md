# Codex Atlas 开发记录

## 2026-07-02 背景收集

- 当前项目起始状态：只有 `docs/Codex能力字典桌面侧边栏工具箱.md`，不是 Git 仓库。
- 本机可用工具：Go `go1.26.4 windows/386`、Node `v24.17.0`、npm `11.13.0`、codex CLI `0.141.0`。
- 本机缺少 Rust、Cargo、dotnet 和可用 C 编译器，因此避开需要 Rust/.NET/CGO 的桌面方案。
- Codex 数据目录：`C:\Users\Administrator\.codex` 存在，包含 `skills`、`plugins/cache`、`sessions`。
- 插件缓存中存在 `.codex-plugin/plugin.json`，插件 skills 位于 `skills/**/SKILL.md`。

## 2026-07-02 方案结论

- 技术栈选择 Go + `github.com/lxn/walk`。
- 所有 Go 缓存必须通过环境变量固定到项目内 `.cache`。
- 扫描和统计只读 Codex 数据目录。
- 用户数据与 AI 数据分层存储，AI 不能覆盖用户字段。

## 2026-07-02 第一轮核心层审查修复

- 子 agent 审查发现 5 个重要问题：写入边界未闭合、插件路径可逃逸、坏 Apps/MCP 清单会中断扫描、插件重名 skill 统计串计、AI 输出未校验结构和 ID 范围。
- 已新增回归测试并修复：
  - `store.NewBoundedJSONStore` 校验项目根目录，生产路径必须在项目内。
  - 插件 manifest 相对路径必须留在插件根目录内，绝对路径和 `..` 会被跳过并记录说明。
  - Apps/MCP 可选清单解析失败时降级为 `SourceNote`，不阻塞本地 skills 和 plugin 扫描。
  - 统计只在 skill 短名唯一时匹配短名，重名插件 skill 优先匹配完整 `$plugin:skill`。
  - AI 整理写入 `.tmp/ai-output.json`，校验 `items` 字段和输入 ID 范围，并把 `TMP/TEMP` 约束到项目内。
- 验证命令：`go test ./internal/store ./internal/scanner ./internal/stats ./internal/ai ./internal/app`。
- 验证结果：通过。
