# Codex能力字典桌面侧边栏工具箱

英文名称：Codex Atlas

## 背景

Codex 可以使用很多 skills、插件、工具和 apps。能力变多之后，用户自己也很难记住当前到底装了什么、每个能力适合做什么、哪些能力经常用、哪些能力只是别人推荐后一直放着。

这个想法希望做一个自用的桌面侧边栏工具箱，用来展示和整理本机 Codex 可用能力。它不是新的聊天工具，也不是 AI 协作控制台，而是一个贴边、置顶、方便随时查看的能力字典。

## 产品定位

这是一个面向个人使用的 Codex 能力字典 App，英文名称为 Codex Atlas。

核心目标是让用户知道：

- 当前 Codex 有哪些 skills、plugins、tools 和 apps。
- 每个能力大概是做什么的。
- 哪些 skill 自己经常用，哪些几乎没用过。
- 需要时应该怎样在 Codex 对话里主动点名调用某个能力。

## 主形态

产品主形态是桌面侧边栏工具箱。

它可以固定在任意软件之上，平时作为一个小的侧边栏或浮窗存在，需要时展开查看。主视图以 `Skills` 为核心，也可以切换到 `Plugins`、`Tools`、`Apps` 等视图。

这个工具不追求做成完整的管理后台，也不追求像启动器一样完全键盘优先。它更像一个随手能打开的 Codex 能力地图。

## 核心功能

### 能力清单

- 扫描本机 Codex 的 skills、plugins、tools 和 apps。
- 本地文件扫描为主，运行时读取为补充。
- 标注每个能力的来源，例如本地 skill 文件、插件缓存或当前 Codex 会话暴露的工具。
- 如果某个能力存在于本地文件但当前会话不可用，可以保留显示并标注状态。

### Skills 主视图

`Skills` 是最重要的视图。

每个 skill 可以展示：

- 中文名或个人别名。
- 真实 skill 名称。
- 标签。
- 简短说明。
- 收藏状态。
- 是否隐藏。
- 使用统计。

真实名称用于准确调用，中文名和别名用于方便用户自己记忆和搜索。

### Plugins、Tools 和 Apps 视图

`Plugins`、`Tools`、`Apps` 可以作为独立切换视图存在。

这些视图主要用来理解 Codex 当前能力环境，不需要和 `Skills` 一样复杂。plugin 可以展示它包含哪些 skills；tools 和 apps 可以展示当前运行时暴露出来的能力说明。

### 标签和个人整理

标签完全面向个人使用，不需要团队规范。

- AI 可以初次帮忙打标签。
- 用户可以随便新增、修改、删除标签。
- 标签可以很口语化，例如 `常用`、`不熟`、`别人推荐的`、`写文档`、`调试`、`GitHub`、`设计`。
- 手动标签优先级最高，AI 后续重新整理时不能覆盖用户自己的标签。

除了标签，还可以支持备注、收藏、隐藏和个人排序。

隐藏项默认不出现在普通列表里，但可以通过隐藏列表找回。隐藏项的统计记录仍然保留。

### 悬停说明和详情

鼠标悬停到某个能力上时，展示一句话说明。

点开详情后，可以看到：

- 更完整的中文摘要。
- 原始描述。
- 适用场景。
- 不适用场景。
- 调用模板。
- 来源路径。
- 使用统计。

### 原始文件入口

每个能力都可以提供几个直接动作：

- 打开原始文件。
- 打开所在目录。
- 复制路径。

对 skill 来说，最常用的是直接打开对应的 `SKILL.md`。

### 调用模板

工具需要支持一键复制调用模板。

例如：

- `请使用 $grill-me 帮我拷问这个想法`
- `请使用 $diagnosing-bugs 帮我系统排查这个问题`
- `请使用 $auto-git-sync 完成后提交并推送`

模板可以由 AI 生成，也可以由用户自己修改。一个能力可以有多个模板，常用模板可以置顶。

这个功能很关键，因为它让能力字典不只是“看见能力”，而是能立刻把能力带回 Codex 对话里使用。

### 使用统计

工具可以读取本机 Codex 历史会话，解析其中出现或使用过的 skills。

统计口径以 skill 为主：

- 真实使用次数。
- 最近使用时间。

主指标应该是“真实使用次数”，优先统计用户显式 `$skill` 调用，以及助手实际读取对应 `SKILL.md` 的记录；系统提示、工具输出和能力清单里的普通提及不应计入。

plugin 可以根据其下 skills 做聚合统计；tools 和 apps 的统计可以后续视情况补充，不作为核心。

### AI 离线整理

工具可以内置 AI 整理能力，但只用于整理字典，不用于实时分析当前聊天。

AI 可以做：

- 生成中文摘要。
- 自动打标签。
- 生成调用模板。
- 总结适用场景和不适用场景。
- 提示相似能力。

AI 生成内容和用户个人内容需要分开存储：

- 原始数据来自能力文件、插件和运行时工具。
- AI 数据包括摘要、标签、模板、适用场景等。
- 个人数据包括用户标签、备注、收藏、隐藏、自定义模板等。

重新运行 AI 整理时，只更新 AI 字段，不能覆盖用户手动整理的内容。

### 手动刷新

刷新行为以用户主动触发为主，不做后台自动扫描。

可以提供几个手动动作：

- 刷新能力清单。
- 刷新使用统计。
- AI 整理当前列表。
- 全部刷新。

这样用户知道工具什么时候在扫描、什么时候在调用 AI，整体更可控。

### 全局快捷键

工具可以支持全局快捷键，用来快速显示或隐藏侧边栏。

快捷键只是唤起入口，不需要把产品做成完整的键盘优先启动器。

## 明确不做的功能

以下功能暂时不作为这个产品的核心方向：

- 场景索引。
- 学习模式。
- 能力健康检查。
- 自动后台刷新。
- 导入和导出备份。
- 专门的熟悉度字段。
- 键盘优先启动器形态。
- 实时读取当前聊天记录并让 AI 判断该用什么能力。
- 自动安装、卸载或更新插件。
- 内置聊天窗口。
- 团队共享、账号系统或云同步。

这些功能不是完全没有价值，而是和“自用能力字典”的主路径相比，实用性或投入产出比不够高。

## 后期可选功能

后期可以考虑加入轻量的当前 Codex 会话感知，但不作为核心依赖。

例如：

- 检测当前是否有 Codex 窗口。
- 读取窗口标题。
- 识别当前工作目录。
- 根据当前目录或项目类型做轻量过滤。

如果这类功能实现成本高或稳定性差，可以直接放弃，不影响核心产品成立。

## 价值

这个工具解决的核心问题不是“让 AI 更聪明”，而是让用户更清楚自己手里有哪些 AI 协作能力。

它让 Codex 的 skills、plugins 和 tools 从一堆隐藏在系统里的配置，变成一个可查看、可整理、可调用的个人能力地图。用户可以在对话中更主动地说“这次请使用某个 skill”，而不是完全依赖 AI 自己判断要不要用、用得好不好。
